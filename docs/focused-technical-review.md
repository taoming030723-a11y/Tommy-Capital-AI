# 观察名单六周期技术评估与ChatGPT解释

入口仍为[私有中文交互报告](https://tommy-capital-report.stableokapi18.chatgpt.site)。本独立观察升级不改变原A/B选股路线、月J入口、月周技术权重、50/50评分、Top10历史或持仓做T规则。之后2026-10-22用户另行授权周MA55及周MACD加权，当前排名分配见[v9说明](weekly-ma55-macd-v9.md)；本页的六周期观察不直接改排名分。

## 北交所忽略修复

东方财富搜索将部分北交所股票标为`Classify=NEEQ`、`SecurityTypeName=京A`、`SecurityType=27`，原校验只认`AStock`，因此920599同力股份、920946森萱医药被错误拦截。现在接受该明确的京A分类，不把其他新三板或同名港股混入A股。

已有观察或持仓身份的忽略直接使用服务器已知代码和名称；外部搜索不可用、股票更名或退市不会阻断移除。新增持仓仍需核验名称。忽略、恢复保持revision比较，不覆盖另一窗口的新设置；持仓优先级保留。

按用户本次要求，`operations/watchlist-preferences.json`将两只股票移出Top10观察。仅观察范围变化，历史累计次数、入池资格和排名不变。网页的恢复按钮可显式恢复。

## 六个周期与买点判断

观察范围仍是累计三个不同正式收盘日进入Top10且未忽略的股票，加网页手动持仓；不要求连续。每只股票展示月、周、日、60、30、15分钟的：

- 完整K线时间、来源、实际根数与缺失原因。
- 股价及MA5、MA13、MA20、MA55，以及价格相对均线的位置。
- 标准EMA12/26、DEA9、`MACD柱=2×(DIF−DEA)`、红绿柱变化及同向连续波段实际峰值比较。
- KDJ(9,3,3)的K、D、J、方向和金叉；严格DIF/KDJ枢轴背离。

均线、EMA、KDJ及严格DIF枢轴与原Python实现进行冻结数据一致性测试。连续柱峰只标动能减弱或疑似背离，不凭柱缩短确认顶底；原Python监控保存的五周期波段事件、确认时间及历史不被改写。此评估不是新的排名引擎。

技术买点沿用原逻辑逐项检查：原月J路径并向上恢复、周MA55非下行及近期守住状态、周结构、原日线量价确认、原月周日趋势，再检查同交易日60分钟MA20、30分钟冲突、15分钟严格MACD底背离、支撑回升、价格收回、量比及过热。周MA55仍要求最近六个完整周至少三次、连续两周在线上，周收盘和最新日收盘均在其上。B路径日线确认仍需首次平台突破。原路线未知时只作技术路径兼容性观察，不补造基本面路线资格。

结果分为“技术买点观察条件齐备”“大周期已确认，等待执行买点”“当前未满足原技术买点条件”“数据未齐，不能确认买点”。即使技术条件齐备，仍需有效基本面资格、人工风险与仓位确认；不下单，不自动授予做T资格。

## 行情更新

网页打开后对当前观察并集逐只评估，并支持“刷新全部技术面”。只请求重点股票，不扫描全部A股。

技术行情日独立于全市场报告：从真实指数交易记录确认最近已完成交易日，15:05以前不使用当天尚未收盘日线。全市场新报告尚未发布时，重点评估仍可更新到已验证的新收盘日，分别显示主报告日和技术行情日。未收到新日数据时保留实际日期，不把旧数据称为当日行情。

腾讯原生前复权日、周、月线分别请求；周/月排除形成中周期，并与日线最近完整周期复权价格核对。分钟使用新浪真实K线，逐交易日匹配原始/前复权日线因子，校验完整交易时段、午休、内部缺根和收盘截止；不使用模拟行情或静默退回未复权价格。日线至少250根、周至少60根、月至少24根、每种分钟至少60根，保持原下限。源不可用时明确数据不足。

每日公开收盘流程也单独评估其公开Top10持续观察名单；新增模块有独立时间预算，保留partial状态，不改变原市场覆盖计数。网页私人持仓仅存私有数据库，不发送到公开GitHub Actions。公开报告的偏好变更也会过滤新增技术评估表，旧结果保留供恢复，不能由旧扫描收尾重新带回已忽略股票。

## ChatGPT接入与凭据

模型通过服务器端OpenAI Responses API接入，使用严格JSON Schema输出六周期解释、综合说明、风险和下一步确认条件。程序买点布尔条件、评分和排名不交给模型修改。模型输入只包含已核验指标、数据状态和既定条件，不含成本、股数、备注或新的基本面研究任务。使用`store=false`。

服务端配置：

| 环境 | 配置 |
| --- | --- |
| 私有手机网站 | 通过OpenAI Developers完成API凭据授权，再通过Sites运行时密钥配置`OPENAI_API_KEY`；不在页面粘贴或公开保存密钥 |
| 可选模型名 | `OPENAI_TECHNICAL_MODEL`，默认`gpt-5-mini` |
| GitHub公开观察解释 | 仓库Actions Secret `OPENAI_API_KEY`及可选Variable `OPENAI_TECHNICAL_MODEL`；不要把网站或本机持仓同步成公开任务 |

没有密钥时显示“ChatGPT尚未连接API；当前为程序规则评估”，不会把模板或测试响应冒充真实ChatGPT分析。接口失败、拒绝、输出未完成或格式错误时，程序技术结果仍保留，模型说明标未完成。模型解释的实时可用性取决于已授权的账户、模型权限与接口限额。

同一完整行情与规则指纹复用同一模型解释；不会因反复点刷新而重复调用模型。不同周期相互矛盾、弱背离和缺失项明确保留。模型未获凭据前，真实模型调用不能验收为完成。

官方资料：[Responses结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)、[GPT-5 mini](https://developers.openai.com/api/docs/models/gpt-5-mini)。

## 基本面与估值只评一次

网页首次已有成功估值或明确PE不适用结果后，按股票存为私有基准；之后跨日技术刷新只读该基准，不重复请求财报、不向ChatGPT重新评基本面。表格显示原基准价、基准日期和原历史PE区间，不把它冒充当天重新估值。

确需重评时，可展开该股估值依据，点击“手动重新评估此股基本面／估值”。原全市场选股的财务核验保持原规则，不用永久旧财报替代新排名的数据要求。

只读服务校验可通过`/api/report?public_technical_code=六位代码`读取未忽略且累计三次的公开观察股技术事实；该入口不读取私人名单、不写数据库、不调用模型。私人持仓及其缓存继续要求真实登录身份。

## 持久化与验证

`report_studies`独立于名单记录，按平台验证用户ID、代码和类型存储技术评估及估值基准；有并发租约和令牌比较，旧刷新不能覆盖新结果，技术刷新也不增加名单revision。schema迁移仅新增表，不改写已有持仓和偏好。

代码：`web-report/lib/technical-review.mjs`、`technical-market.mjs`、`ai-technical.mjs`、`studies.ts`；接口`app/api/technical-reviews/route.ts`；收盘附加脚本`scripts/attach-technical-reviews.mjs`；中文报告渲染`tommy_capital/focused_reporting.py`。

测试使用冻结数据和明确的模型解析桩；桩只用于测试，不进入真实报告。执行`python -m pytest -q`、`node --test web-report/tests/*.test.mjs`，并做TypeScript和生产构建。真实行情验证须记录实际行情日与缺失情况，模型未配置时不声称完成真实API验证。
