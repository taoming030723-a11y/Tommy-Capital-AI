# 多周期K/D状态观察

按2026-10-23用户提供的思路，在原系统上增加独立描述层。生产`weekly_ma55_macd_50_50_v9`、基本面50／月线20／周线30、周MA55的16分、原月J入口、基本面路线、Top10累计、忽略/恢复及做T规则均不变。

## 在哪里看

打开[原私有交互报告](https://tommy-capital-report.stableokapi18.chatgpt.site)，进入观察或持仓技术评估，点击原“刷新全部技术面”。下方新增“多周期K/D状态观察”：可筛选全部、转折/交叉/减弱及数据缺口，展开每股查看各周期最近6根完整K线的K、D、派生J、K−D、来源、截止时间及最近交叉。

范围仍是未忽略的累计至少三个不同正式收盘日Top10观察股、私人手动观察与当前明确持仓；持仓优先于观察忽略。普通Top20不因此扩成全市场分钟监控。私人持仓不写入公开报告或公开研究队列。旧缓存没有轨迹时提示刷新，不根据旧报告单个K/D值补造历史。

公开收盘Markdown在原Top20、累计表和技术观察中增加独立K/D表，JSON保留完整轨迹。Windows本机MACD监控复用已有真实K线生成同定义的K/D描述，不增加日内全市场扫描。

## 具体状态

配置位于`kd-state-config.json`，网页镜像为`web-report/lib/kd-state-policy.json`，测试保证二者一致。采用原KDJ(9,3,3)与50初值；不修改原KDJ、MACD或评分计算。默认明确升降阈值为每根0.5个K/D指标点，间距收窄阈值也是0.5点；这是透明待验证参数，不是已优化权重。

| 状态 | 完整K线观察条件 |
| --- | --- |
| 低位弱势 | 当前K、D均≤20，K<D，二者均明确下降 |
| 早期转折 | K明确向上，D尚未达到明确上行阈值；可在K尚未上穿D或D仍缓慢跟随时出现 |
| 低位金叉 | 前根K≤D、本根K>D；交叉前根K、D均≤20 |
| 偏多延续 | 已在K>D状态，K、D共同明确上行；不把持续多头每天重复叫金叉 |
| 动能减弱 | K明确回落，仍未死叉，原正K−D间距明确收窄 |
| 偏空转折 | 前根K≥D、本根K<D；并非自动认定整轮趋势结束 |

非低位金叉另标“金叉（非低位）”；其他下降或不一致状态分别为偏空延续、中性整理、方向未一致。交叉发生优先于延续状态。跨线间距不足0.5点时显示“小间距交叉”，不冒充强确认。低位是K、D的状态定义，**不替代原月J选股门槛**。

每根保留日期、K、D、J及K−D；J=3K−2D=K+2(K−D)，不当作另一个独立确认或重复奖励。这里只确认完整K线上的指标状态，不授予价格反转、MACD严格背离、新开仓或持仓做T资格。

## 周期、完整性与相关性

观察月／周／日／120／60／30／15七个周期，原技术买点条件仍只有既定六周期，120只附加在独立K/D层。`kd_monitor.data_complete`独立于原六周期技术完整性；120缺失不会偷偷改原条件，也不会被说成没有信号。

120分钟从已核验的60分钟数据合成：10:30+11:30为上午一根，14:00+15:00为下午一根。严格按真实交易日历，不跨午休、跨交易日拼接；拒绝内部缺根，数据窗口开头不完整半场可丢弃。网页无额外120分钟行情请求。

最低历史保持月24、周60、日250、分钟各60根；最近6根K/D必须真实有限，暖启动缺值不填0。Python本机监控周/月从已核验日线聚合并排除未完成周期；网页复用原已核验原生周/月线。不同来源和起始历史明确保留，不能把时点不同的数据当成同一根。

展示月线战略、周线趋势、日线确认、120/60结构组、30/15执行组。相关组保留各自状态，但不通过“两个信号”堆出更高评分；只有单一15分钟金叉不代表中期反转。方向冲突标“周期K/D分歧”。不存在新K/D总分、信号数量置信度或自动交易权限。

## 如何验证是否有增量价值

公开技术观察后生成`kd-observation-snapshot.json`，包含实际决策生成时间、原行情日、生产版本、配置、公开范围及各周期轨迹，带SHA256。它与原生产研究快照独立，原排名和Top10历史不改写。补研究旧收盘数据时使用**实际生成时间**，不回填为前一天已知道的决策。忽略变化会在发布前过滤，私人观察及持仓不进入公开快照。

正式发布至`research/kd-observations/实际生成日/哈希.json`。后续原研究任务读取最近20份独立记录，复用原真实交易日历、前复权价格和成本核验，观察决策之后首个交易日开盘起的1/5/20/60交易日结果。停牌、缺日、单价入场K线等继续保持缺失；不从样本中静默删掉。

分组按K/D配置哈希和生产模型版本拆开；每个状态的结果与**同一决策日、同一观察池**平均表现匹配比较，避免仅因不同日期市场涨跌而误称增量。输出`kd-forward-evaluation.json`，发布至`research/latest-kd-evaluation.json`。相关周期不会合成多次独立样本。

这属于前瞻条件分组观察，**尚未证明K/D能提高收益**，也不是已解决公告时点、退市样本、成交约束、多重检验和市场风格偏差的全市场回测；状态保留`unvalidated_out_of_sample`。程序不自动训练或替换生产权重。

## 工程与运行

核心文件为`tommy_capital/kd_state.py`、`kd_research.py`、`kd_reporting.py`以及网页`lib/kd-state.mjs`、`app/kd-observations.tsx`。两种运行环境用冻结数据逐根重放及跨语言一致性测试校验，公式复用原KDJ。

原15:05及补检计划、股票limit=0不变。正式收盘重点技术步骤自动附加K/D；投资研究步骤冻结新观察。已有`enrich-report.yml`可显式选择刷新公开重点技术池，只复用指定源报告的日期，不重新扫描全市场或重复估值；来源证明分别标记全市场请求为0与是否请求重点刷新。所有原评分、日期、研究快照及发布审计继续执行。
