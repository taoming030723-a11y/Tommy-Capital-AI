# 收盘扫描触发与启动状态

主任务仍由GitHub Actions在北京时间／新加坡时间交易日15:05触发，15:35和16:05补检。GitHub的`schedule`是尽力调度，可能延迟或丢弃；添加同平台cron不能保证准点。

另设ChatGPT独立检查，在工作日15:10、16:10、17:10读取真实Actions状态和当天报告。已经排队／运行时不重复触发；有效当天最终报告（包括如实标记的partial）已发布时不重扫。没有运行和有效报告才写入下面的补启动请求，每天最多两次。真实交易日和行情完整性继续由扫描器核验；休市不生成当天行情。

## 独立请求格式

通过GitHub连接器把`operations/scan-request.json`提交到`main`，触发`screen.yml`的`push`入口；不要使用`[skip ci]`消息。只改这个请求文件，保留所有现有代码和报告。

```json
{
  "schema": 1,
  "scan_phase": "closing",
  "requested_for": "2026-10-13",
  "requested_at": "2026-10-13T15:10:00+08:00",
  "attempt": 1,
  "reason": "今日收盘扫描未进入排队或运行，独立补启动"
}
```

日期和时间必须填写实际请求日与请求时间。`attempt`限1或2；同日重复检查不得重置次数。请求必须在15:05之后、不能来自未来，超过2小时过期；次日排队的旧请求不执行。它始终为收盘模式、`--limit 0`，不改变任何选股、复权、历史长度、估值或下单权限。串行并发组不取消正在运行的扫描；进入队列后再次读取主分支，若当天报告已经发布则跳过。

## 当前状态与最终结果

`results/scan-status.md`和`scan-status.json`独立记录实际运行身份、启动和状态。扫描开始时`latest-report.md`顶部提示“正在扫描”，下方保留上一份真实报告并标其数据日；`latest-summary.json`继续保持上一份已审计最终结果。启动状态不冒充新的选股结论。

扫描结束，审计及中文发布成功后移除运行提示，并写入完成／partial状态。扫描失败或发布失败如实显示。旧运行的延迟收尾不能覆盖新运行状态。状态显示服务失败不会中断真实行情扫描；独立检查会按Actions和已发布报告校正状态。
