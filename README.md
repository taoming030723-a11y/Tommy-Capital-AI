## 两条独立路线

| 项目 | A 已兑现／深度反转 | B 领先业务／产品拐点 |
|---|---|---|
| 基本面 | 原盈利、增长和现金流要求；现金流/股为正且不低于上年同期 | 营收同比>10%；当前利润、TTM利润和现金流必须有真实数值，允许为负 |
| 估值 | 正TTM利润计算PE≤60、PB≤8、PE/行业中位数≤1.2，行业有效样本≥5 | 已复核的正常化远期盈利、SOTP或EV-Sales三情景估值；不豁免估值 |
| 月J入口 | 当前完整月J<20，或最近3个完整月曾J<20且当前J>上一完整月 | 最近6个完整月曾J<20且当前J>上一完整月 |
| 压缩路径 | 月J路径 | 另需近126个交易日从在先峰值到后续低点曾回撤≥20%，这是价格压缩代理 |
| 领先证据 | 基本面改善只作观察加分 | 销量或订单增长>30%，或新产品实际规模交付；核心业务改善；未来6个月明确催化，均须核对 |
| 周线 | 原6周量价筑底，扩展低点抬高、波动收敛、平台突破 | 同左 |
| 日线战略确认 | 最新完整日线RVOL20≥2或有效首次平台放量突破 | 必须有效首次平台放量突破 |
| 15分钟 | 展示顶底背离、金叉、回踩、过热、无信号；不作为选股硬条件 | 同左 |

观察池仅要求相应基本面、估值、流动性和月J路径，B还需价格压缩。**战略量价确认**另要求月J向上、至少一种周结构成立，以及对应日线量价确认。均线可以尚未全部转多而进入观察池；原日／周／月均线确认状态另列。

A路线使用已公告累计营收／归母净利增长。TTM利润＝上一年度全年＋本期累计−上年同期累计，数据缺失不替换为0。现金流比较的是上年同季累计每股经营现金流，不能拿一季与半年累计数比较；股本变动、金融行业现金流及扣非仍需专项复核。

## 日线量价计算

`RVOL20 = 检测日成交量 / 此前20个完整交易日平均成交量`，分母**不含检测日**。

- 普通异常量仍为≥2倍。
- 首次平台放量突破单独使用≥1.5倍，收盘>此前20日最高价，`(close-low)/(high-low)≥0.65`，此前20日平台高低振幅≤20%。
- 在最近20个交易日中逐日因果检测，每个事件仅使用当时已完成的K线与在先20日基准；同一突破后的连续上攻不重复报警。保留首次日期、事件量比、平台价、确认时间与是否仍守住平台。
- 早盘使用上一完整日线；不把未完成早盘成交量与20天全天均量比较。

周线筑底原代理要求6周窄幅、低点稳定、收盘守住均值及日均量平稳；按每周真实交易日数归一，休市短周不会因天数少被误判缩量。新增结构为后3周低点抬高并守均值、未创新低的波动收敛、收盘突破此前6周高点。它们不能证明主力吸筹。

## 领先证据与估值覆盖

[evidence/leading-inflections.json](evidence/leading-inflections.json)是通用证据登记文件，适用于任意六位证券代码，**不是白名单**。每次运行重新请求登记的官方HTTPS页面，核对发布日期、事实文本和SHA256；来源访问失败、文本变化、未来/过旧发布均不通过，不能偷偷使用过期快照。

目前只登记江淮S800规模交付的官方资料。它能证明规模交付，不能把累计交付数当作同比增长率。V800/V680于2026-08-05已上市，不能在10月7日被当作“未来上市催化”。现有资料缺少未来催化及已复核三情景估值，江淮不会被自动特批。以前讨论的正常化利润和PE区间属于研究假设，没有完整可复核来源不能直接写成官方盈利。

公开财报可自动检查营收及毛利率同比改善代理；核心业务改善仍可用有来源的经营证据确认。没有可靠免费接口自动补齐几千家公司的订单、单品销量、未来催化和SOTP，**B证据覆盖目前有限**。所有报价股票仍评估A/B预检；B营收预检合格者会请求技术检查并列出证据缺口，资料未齐只在待核实记录中出现，不混入主候选。报告明确列出登记、请求、验证及缺失数量，因此不能把报价覆盖称为全部市场研究检查完整。

三情景估值需`reviewed=true`、90天内`as_of`、未来2年内`forecast_year`、明确`assumption_basis`及本次核对通过的`source_ids`。Bear/Base/Bull分别录入：

| method | 每个scenarios情景必需字段 | 计算 |
|---|---|---|
| normalized_forward_profit | net_profit_cny、pe | 正常化归母净利润×PE |
| sotp | segments各分部enterprise_value_cny、net_debt_cny | 分部企业价值之和−净债务 |
| ev_sales | revenue_cny、ev_sales、net_debt_cny | 营收×EV/Sales−净债务 |

默认Base安全边际≥20%，Bear潜在跌幅≤30%，远期PE≤30，EV-Sales倍数≤4；均为透明研究阈值。三情景必须为正且Bear≤Base≤Bull。经营数据与研究假设分开，情景利润不是官方承诺。

## 15分钟执行与持仓做T

中文报告单列“基本面、大周期通过的15分钟执行／做T观察”，并列出确认时间及未满足条件。

主观察池同时显示15分钟背离、金叉、回踩反弹、过热和无信号；这些状态不影响选股资格。回踩反弹要求上一根收于MA20上、本根触及MA20后收回其上且收盘高于上一根，不能把所有站上均线的K线都叫回踩。

做T采用更严格条件：已入观察池、战略量价确认，并通过原日/周/月均线规则（日收盘>MA60且MA20上升，周收盘>MA20且MA20不下降，月收盘>MA20）。底背离还要结合确认枢轴支撑附近反弹、价格结构收复、15分钟量比≥1.2、当日已完成60分钟位于MA20上、30分钟无顶背离冲突。15分钟J>100且收盘>MA20×1.03时标过热，须等待降温。09:50当日60分钟尚未完成，会如实标等待。顶背离用于减仓／过热风险观察。

**实际做T资格还必须是明确当前持仓**。未提供持仓时默认空集；不把历史聊天持仓当作当前持仓。合格但持仓未确认的股票只显示执行观察，不显示做T进场资格。A股当日新买股份不能当日卖出，无订单执行功能。

## 电脑一条命令运行

需要Python 3.11或更新版本：

```bash
python run.py
python run.py --daily-only
python run.py --limit 10
python run.py --scan-phase opening
python run.py --scan-phase closing
python run.py --minute-scope screened
python run.py --output reports/manual
```

默认使用`config.json`和官方证据文件；若本地存在`holdings.json`会加载，也可用`--holdings 路径`明确指定。持仓格式`{"holdings": ["六位代码"]}`，示例文件不代表真实持仓。GitHub默认不设置任何用户持仓。

盘中要求09:45:30之后有当天已完成15分钟K线。收盘模式要求15:10之后已确认当天完整日线和15:00分时；旧行情不允许作为当日收盘发布。分时跨除权使用独立原始／前复权日线配对，缺少因子直接标不可用。日线至少250根、周线至少60根、月线至少24个完整月份；未完成周月不参与确认。

## 报告与状态

`reports/latest/`包含完整`report.json`、`summary.json`、中文`report.md`、HTML及rankings/observations/excluded/divergences CSV。CSV保留六位代码，文本进行公式安全处理。JSON保留行情来源、抓取时间、哈希、技术条件和逐股排除原因。

- `selection_rule=dual_route_monthly_recovery`。
- `eligible`＝观察入池；`strategic_eligible`＝战略量价确认；`t_trend_confirmed`＝再通过原日周月均线；这三层不等同买点。
- `candidate_count`＝全部观察候选数，`top_candidates`前15不是总数；A/B以主路线计数，另保留全部通过路线。
- `scan_complete=false`表示存在技术、数据、证据或未扫描缺口。部分结果仍发布，退出码1会使Actions显示failure，不代表全部数据断开。全局失败退出2。
- 扫描中检查点不发布为最终结果；Markdown与JSON日期、状态、模式、覆盖及候选数必须一致，使用单个Git提交原子发布。开盘与收盘独立日期归档。

`python -m pip install -e '.[test]'`后运行`python -m pytest -q`。离线测试只验证公式和控制流程，从不作为真实报告。真实扫描需Actions实际运行及附件核对；历史预跑见[VALIDATION.md](VALIDATION.md)，旧规则人数不能复用为新模型结果。

数据采用新浪沪深北目录、东方财富已公告财报、腾讯/东方财富/带可验证复权因子的新浪日线与新浪分时。公开接口可能限流、停牌、缺历史或更新滞后，缓存仅复用仍有效的数据，缺失不会生成模拟行情。
