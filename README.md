## 两条独立路线

| 项目 | A 已兑现／深度反转 | B 领先业务／产品拐点 |
|---|---|---|
| 基本面 | 原盈利、增长和现金流要求；现金流/股为正且不低于上年同期 | 营收同比>10%；当前利润、TTM利润和现金流必须有真实数值，允许为负 |
| 估值 | 正TTM利润计算PE≤60、PB≤8、PE/行业中位数≤1.2，行业有效样本≥5 | 已复核的正常化远期盈利、SOTP或EV-Sales三情景估值；不豁免估值 |
| 月J入口 | 当前完整月J<20，或最近3个完整月曾J<20且当前J>上一完整月 | 最近6个完整月曾J<20且当前J>上一完整月 |
| 压缩路径 | 月J路径 | 另需近126个交易日从在先峰值到后续低点曾回撤≥20%，这是价格压缩代理 |
| 领先证据 | 基本面改善只作观察加分 | 销量或订单增长>30%，或新产品实际规模交付；核心业务改善；未来6个月明确催化，均须核对 |
| 周线 | 原6周量价筑底，扩展低点抬高、波动收敛、平台突破 | 同左 |
| 日线战略确认 | 最新完整日线RVOL20≥2或有效首次平台放量突破 | 必须有效首次平台放量突破 |
| 15分钟 | 展示顶底背离、金叉、回踩、过热、无信号；不作为选股硬条件 | 同左 |

观察池要求相应基本面、估值、流动性、原月J路径，以及非下行且被近期价格守住的周MA55强化门槛，B还需价格压缩。**战略量价确认**另要求月J向上、至少一种周结构成立，以及对应日线量价确认。短均线可以尚未全部转多而进入观察池；原日／周／月执行趋势确认仍独立保留。B还新增下文的财报亏损收窄子路线，不把它冒充领先催化证据齐全。

A路线使用已公告累计营收／归母净利增长。TTM利润＝上一年度全年＋本期累计−上年同期累计，数据缺失不替换为0。现金流比较的是上年同季累计每股经营现金流，不能拿一季与半年累计数比较；股本变动、金融行业现金流及扣非仍需专项复核。

## 日线量价计算

`RVOL20 = 检测日成交量 / 此前20个完整交易日平均成交量`，分母**不含检测日**。

- 普通异常量仍为≥2倍。
- 首次平台放量突破单独使用≥1.5倍，收盘>此前20日最高价，`(close-low)/(high-low)≥0.65`，此前20日平台高低振幅≤20%。
- 在最近20个交易日中逐日因果检测，每个事件仅使用当时已完成的K线与在先20日基准；同一突破后的连续上攻不重复报警。保留首次日期、事件量比、平台价、确认时间与是否仍守住平台。
- 早盘使用上一完整日线；不把未完成早盘成交量与20天全天均量比较。

周线筑底原代理要求6周窄幅、低点稳定、收盘守住均值及日均量平稳；按每周真实交易日数归一，休市短周不会因天数少被误判缩量。新增结构为后3周低点抬高并守均值、未创新低的波动收敛、收盘突破此前6周高点。它们不能证明主力吸筹。

## 领先证据与估值覆盖

[evidence/leading-inflections.json](evidence/leading-inflections.json)是通用证据登记文件，适用于任意六位证券代码，**不是白名单**。每次运行重新请求登记的官方HTTPS页面，核对发布日期、事实文本和SHA256；来源访问失败、文本变化、未来/过旧发布均不通过，不能偷偷使用过期快照。

目前只登记江淮S800规模交付的官方资料。它能证明规模交付，不能把累计交付数当作同比增长率。V800/V680于2026-08-05已上市，不能在10月7日被当作“未来上市催化”。现有资料缺少未来催化及已复核三情景估值，江淮不会被自动特批。以前讨论的正常化利润和PE区间属于研究假设，没有完整可复核来源不能直接写成官方盈利。

公开财报可自动检查营收及毛利率同比改善代理；核心业务改善仍可用有来源的经营证据确认。没有可靠免费接口自动补齐几千家公司的订单、单品销量、未来催化和SOTP，**B证据覆盖目前有限**。所有报价股票仍评估A/B预检；B营收预检合格者会请求技术检查并列出证据缺口，资料未齐只在待核实记录中出现，不混入主候选。报告明确列出登记、请求、验证及缺失数量，因此不能把报价覆盖称为全部市场研究检查完整。

三情景估值需`reviewed=true`、90天内`as_of`、未来2年内`forecast_year`、明确`assumption_basis`及本次核对通过的`source_ids`。Bear/Base/Bull分别录入：

| method | 每个scenarios情景必需字段 | 计算 |
|---|---|---|
| normalized_forward_profit | net_profit_cny、pe | 正常化归母净利润×PE |
| sotp | segments各分部enterprise_value_cny、net_debt_cny | 分部企业价值之和−净债务 |
| ev_sales | revenue_cny、ev_sales、net_debt_cny | 营收×EV/Sales−净债务 |

默认Base安全边际≥20%，Bear潜在跌幅≤30%，远期PE≤30，EV-Sales倍数≤4；均为透明研究阈值。三情景必须为正且Bear≤Base≤Bull。经营数据与研究假设分开，情景利润不是官方承诺。

## 15分钟执行与持仓做T

中文报告单列“基本面、大周期通过的15分钟执行／做T观察”，并列出确认时间及未满足条件。

日线及15/30/60分钟技术观察仅对累计正式收盘Top10至少3次且未忽略的股票与明确持仓开放；普通Top20不扩展成分钟监控池。这些观察不影响选股分数。回踩反弹要求上一根收于MA20上、本根触及MA20后收回其上且收盘高于上一根，不能把所有站上均线的K线都叫回踩。

做T采用更严格条件：已入观察池、战略量价确认，并通过原日/周/月均线规则（日收盘>MA60且MA20上升，周收盘>MA20且MA20不下降，月收盘>MA20）。底背离还要结合确认枢轴支撑附近反弹、价格结构收复、15分钟量比≥1.2、当日已完成60分钟位于MA20上、30分钟无顶背离冲突。15分钟J>100且收盘>MA20×1.03时标过热，须等待降温。09:50当日60分钟尚未完成，会如实标等待。顶背离用于减仓／过热风险观察。

**实际做T资格还必须是明确当前持仓**。未提供持仓时默认空集；不把历史聊天持仓当作当前持仓。合格但持仓未确认的股票只显示执行观察，不显示做T进场资格。A股当日新买股份不能当日卖出，无订单执行功能。

## 电脑一条命令运行

需要Python 3.11或更新版本：

```bash
python run.py
python run.py --daily-only
python run.py --limit 10
python run.py --scan-phase opening
python run.py --scan-phase closing
python run.py --output reports/manual
```

默认使用`config.json`和官方证据文件；若本地存在`holdings.json`会加载，也可用`--holdings 路径`明确指定。持仓格式`{"holdings": ["六位代码"]}`，示例文件不代表真实持仓。GitHub默认不设置任何用户持仓。

盘中要求09:45:30之后有当天已完成15分钟K线。收盘模式可从15:05开始，但仍必须核验当天完整日线和15:00分时；启动时间不代表数据已经更新，旧行情不允许作为当日收盘发布。分时跨除权使用独立原始／前复权日线配对，缺少因子直接标不可用。日线至少250根、周线至少60根、月线至少24个完整月份；未完成周月不参与确认。

## 每个交易日自动收盘扫描

GitHub Actions设为北京时间／新加坡时间每个交易日15:05启动（UTC `5 7 * * 1-5`），使用实际A股交易日历跳过节假日。原2026-10-08的09:50开盘任务保留单次日期保护；每日收盘任务不受该日期限制。代码提交运行回归检查，市场扫描由定时或手动启动，且新任务不会中断正在运行的扫描。

15:35、16:05另设补检以减少单次触发延迟或遗漏的影响。所有市场任务串行运行；排队任务开始时读取main最新版本及当天中文／JSON归档，仅在无有效收盘报告时补扫。有效partial仍保留缺失与`scan_complete=false`，不会为消除红色Actions状态而重复或降低要求；手动启动仍可明确重扫。GitHub定时仍可能延迟，补检不等于精确时刻保证。

每日默认 `--limit 0`，读取实际沪深北报价目录，对全市场逐股做基本面与估值初筛，对全部报价A股请求日周月技术检查（包括财务不通过者），单股源失败只对该股票做一次忽略缓存的恢复；历史不足仍保留未解决标记，按月线20/周线30及基本面50计算综合评分；仅对累计Top10观察与明确持仓请求日线MACD和60、30、15分钟执行观察，中文仅展示TOP20。不能把报价覆盖等同所有股票的日线、15分钟和领先证据均完整。

收盘全局数据校验失败会保留失败诊断，间隔60秒重新获取真实数据，最多重试2次。局部历史、分时或B证据缺失仍标 `partial/scan_complete=false`，不会通过放宽条件改成完整。扫描结束自动联合发布[最新中文报告](results/latest-report.md)、机器摘要及 `results/YYYY-MM-DD/closing-report.md`日期归档，Actions显示同一中文报告并提供完整附件。GitHub排队及行情接口更新可能使实际启动、完成晚于15:05。

## 报告与状态

`reports/latest/`包含完整`report.json`、`summary.json`、中文`report.md`、HTML及rankings/observations/excluded/divergences CSV。CSV保留六位代码，文本进行公式安全处理。JSON保留行情来源、抓取时间、哈希、技术条件和逐股排除原因。

- `selection_rule=dual_route_monthly_recovery`。
- `eligible`＝观察入池；`strategic_eligible`＝战略量价确认；`t_trend_confirmed`＝再通过原日周月均线；这三层不等同买点。
- 中文Markdown、Actions摘要与HTML展示通过原基本面估值、流动性及月线入口、评分齐全的最高20只研究对象，并标明等待月J拐头／等待周线／等待日线／周日量价已确认。日线和分钟周期均不计入研究排名；其中技术观察仅向持续Top10观察股及明确持仓开放。进场与做T门槛不变。此外单列正式收盘前10累计至少3次的股票，每天观察完整日线量比；不足20只按实际展示，不凑数、不为亏损股预留名额。
- `candidate_count`＝全部观察候选数，`top_candidates`最多20只不是总数；A/B以主路线计数，另保留全部通过路线。
- `scan_complete=false`表示存在技术、数据、证据或未扫描缺口。部分结果仍发布，退出码1会使Actions显示failure，不代表全部数据断开。全局失败退出2。
- 扫描中检查点不发布为最终结果；Markdown与JSON日期、状态、模式、覆盖及候选数必须一致，使用单个Git提交原子发布。开盘与收盘独立日期归档。
- 启动状态另记在[当前扫描状态](results/scan-status.md)，扫描开始时中文页顶部显示当天正在生成、上一份报告的数据日及实际Actions链接；机器摘要继续保留最近已审计结果。扫描结束再发布最终结论。
- 除原GitHub定时外，独立检查可通过有日期、时区、真实交易日和每日两次上限的请求补启动。已排队／运行或有效当天报告已发布时不重复扫描。[触发及恢复约束](operations/README.md)列明平台延迟与限制，不承诺定时零延迟。

## 50/50综合研究评分

`scoring_version=weekly_monthly_only_50_50_v8`。按用户最后追加要求，技术评分只保留完整月线和周线，日线及分钟周期不参与排名；基本面50分、技术面50分不变。旧评分及买点讨论保留为历史记录；当前规则见[独立监控与v8模型说明](docs/macd-monitor-v8.md)。

| 部分 | 满分 | 分项 |
| --- | ---: | --- |
| 基本面 | 50 | 营收4、盈利质量/领先或亏损改善14、现金流14、估值14、改善4 |
| 月线 | 20 | 月J路径3.75、低点稳定1.25、MA5/13/20结构5、KDJ2.5、完整月量5、MACD动量1.25、确认底背离1.25 |
| 周线 | 30 | MA55专项12、周结构3.6、短均线1.8、KDJ1.8、完整周量7.2、MACD动量1.8、确认底背离1.8 |
| 日线、120/60/30/15分钟 | 0 | 独立监控与原执行确认，不影响评分和排名 |

完整周/月量与此前20个完整同周期均量比较，排除检测周期和未完成周期：量比≤1得0，1～2倍线性增加，≥2倍获得该量能项满分。缺失不补分，也不分摊权重。原日线2倍异常量、1.5倍首次平台放量突破及收盘位置要求仍保留为战略/执行确认条件。

**周MA55强化入池门槛**：使用已完成周线，MA55状态不下行（rising/flat），最近完整周及最新完整日收盘均在线上，近6周至少3周且连续2周在线上。缺失不通过。专项12分保留原口径：当前位置4、均线斜率最高3、近6周持续守住最高3、真实回踩/上破后下一完整周守住最高2。每一历史周对比当周MA55，日价只比较已知完整周MA55，不用今天的均线回看过去。

累计观察仍是三个不同正式收盘日进入Top10，不要求连续。原[忽略/恢复入口](https://github.com/taoming030723-a11y/Tommy-Capital-AI/actions/workflows/watchlist.yml)及`operations/watchlist-preferences.json`继续生效，不改累计记录、全市场范围或Top20。忽略同步退出观察监控，恢复后重新纳入；明确本机持仓独立于忽略设置。

不足20只按实际展示；强化MA55门槛可能使候选减少，不填充不合格股票。原A、原B领先证据、月J双路线、复权/历史/时效及做T门槛保留。只有下述新增亏损收窄B子路线按本次授权放宽基本面资格。

营收增长仅4分，不直接给利润同比暴增加10分。A盈利质量14分为TTM扣非/归母利润8、扣非利润率2、ROE2及同期核心利润率改善2。现金流14分为实际TTM经营现金流/归母利润最高8、当期经营现金流为正2、同比不恶化2、TTM现金流为正2；不以每股现金流除以不同股本口径的EPS。估值PE/PB/行业PE为5/3/6；核心改善最高4分，上年同期利润率低于1%时增长项上限减半（增长只占此项2分）。利润表、现金流表与原业绩报表按代码、报告期、公告日期和收入/利润金额核对；总额不一致或尚未公告不使用。

原B领先子路线继续保留全部官方业务、核心改善、未来催化与三情景估值证据条件。其盈利质量为已验证领先业务8、官方核心改善3、真实同比核心亏损/利润率改善3；现金流为负不获正现金流加分，亏损TTM不使用负利润转化率，而按TTM现金流/营收贡献评分。B估值按审阅Base安全边际9和Bear风险5，改善项为官方核心改善及未来催化各2。缺失不通过、不为某个股票或亏损股预留名额。

新增B亏损收窄子路线（`leading.variant=loss_recovery`）：TTM仍亏损，连续两个最新报告期的归母及扣非亏损分别较各自上年同期收窄≥10%，扣非利润率提高，经营现金流同比不恶化，营收同比≥0。利润、营收、扣非与现金流总额必须匹配已公告报表和最新行；缺一不通过。保留真实流动性、财报时效、非ST、月J近6月恢复、价格压缩及周MA55门槛。估值要求实际市值/TTM营收PS≤3及PB≤8；这是PS/PB风险限制，不是EV/Sales或未来正常化PE安全边际证明。该子路线不假称未来催化已核验。详细评分见v8说明。

原MACD严格确认保持：两个价格枢轴，右侧3根完成K线，间距≥5根、价格延伸≥0.2%且≥0.15ATR、DIF改善≥0.1ATR、DIF顶背离同在零轴上/底背离同在零轴下，右侧回落/反弹≥0.3ATR且未破坏枢轴。排名只读取周/月严格信号。新增独立五周期柱波监控另见下节；疑似、动能减弱均不授予交易资格。

`ranking_complete=false`与具体原因单独记录：全报价请求不等于成功检查、更不等于全市场研究齐全。存在技术历史/复权/日期缺口、B证据未齐或评分缺失时，TOP20明确为已核验范围内的研究排名。`candidate_count`仍是完整月线观察池，`ranking_eligible_count`为评分齐全的研究池，`confirmed_ranking_count`为其中周日量价已确认的数量。金融行业不使用通用CFO/利润评分，专门风险指标未核验时不进研究排名，缺失不重分配其14分。15:05、15:35、16:05的定时和真实交易日历保护保持，股票并发为8。

月线评分先请求腾讯最多300根真实前复权月线（长历史未核验时独立请求原120根来源），排除未完成月份；与日线覆盖的全部完整重叠月份逐项核对OHLC，价格锚点或完整月份不一致时不使用独立月线。合格观察候选另请求最多300根真实前复权周线，不可核验时尝试180根并保持原日线聚合记录；全部完整重叠周OHLC同样核对，以补足可得MA144/233。保留至少60个完整周、24个完整月的战略历史要求和MACD背离至少35根要求；数据源不可用时保留日线聚合及缺失标记，不降低标准或把未知写成无背离。

日线原始OHLC仍对全市场请求以核验时效、复权、周月聚合、流动性和原战略量价条件；日线MACD及分钟技术观察只对累计Top10观察股与明确持仓请求。分钟缺失独立报告，不改变周/月排名分；`score_inputs_complete`、`score_missing_inputs`及覆盖明确记录缺口。缺失不被视为“没有背离”。JSON/CSV保留每只的`fundamental_score`、`technical_score`与`score_breakdown`。

## 模型复核与后续验证

休市日的模型升级通过`research-review.yml`读取本仓库已验证的真实收盘附件，核对GitHub附件SHA256与完整源报告哈希，再重新评分。复核只接受同一现行评分版本且已有周/月MA、KDJ和逐周MA55原始记录的源附件。旧版未经过强化MA55及亏损子路线验证，不能直接改标v8，需新的真实扫描。报告标`scan_phase=scan_type=model_review`，同时显示原行情日期、原扫描时间和新复核时间；不发新行情请求，不修改原始财务/量价/背离/失败输入，不覆盖旧收盘归档。它不是新的交易日扫描，也不是历史收益回测。

每次收盘与模型复核冻结版本、配置、名单及决策完成时间，保存在`research/snapshots/`；之后按真实交易日历检查决策日之后首个交易日开盘至第1/5/20个交易日收盘的价格表现。使用同一次真实前复权响应，不把不同时点复权价格拼接，不用报告当天已收盘价假装可成交入场。停牌缺K线、重复日期、单价K线或非法价格都标缺失，不从分母静默删除。每边20bp仅是透明研究成本假设，非真实手续费或可成交保证。

冻结记录带SHA256，评价时拒绝改写的名单；模型复核发生在周末则从新的决策时间开始跟踪，不回填成之前已经知道的选股。最近20份记录及当前记录的逐股评价存入`research/latest-evaluation.json`，评价数据保留在完整JSON/附件；精简中文报告不展开模型验证统计。当前没有基准超额收益比较、完整交易模拟或充分独立样本外验证，因此状态始终保留`unvalidated_out_of_sample`，不自动训练权重、不据此保证收益。评价服务失败不会阻止真实扫描与诊断报告发布，也不会伪造评价结果。

日线历史不足与最新日期滞后分别报告：真正短历史不重复下载同一份历史，最新日期或旧混合错误保持可重试并核对备用源。所有原来的250日、60周、24完整月、复权与行情日期/价格检查保持。

## 前10累计与精简收盘报告

每个正式收盘交易日按当日实际综合榜的前10计一次，跨评分版本保留原榜和版本，不追溯重排历史。当天重跑替换该日名单，不累加次数；失败、预跑、盘中及模型复核不计次数。累计至少3次即进入持续观察表，不要求连续3天；当前退出主榜仍保留跟踪，不因此获得选股或做T资格。初始记录按实际10月8日、9日、12日、13日收盘归档回填。

`results/top10-history.json`保留每个收盘日的原前10、分数、时间、版本、运行链接及名单SHA256，与新最终Markdown、机器摘要、日期归档在同一提交中发布。每次报告的`top10_tracking`保留次数、日期、当日综合名次和最新完整日线量比；日线缺失明确未核验，不复用旧日量。

中文Markdown、Actions摘要及HTML统一为扫描概况表、综合前20表、累计至少3次跟踪表，再按顺序给前20的实际财务、月J路径、周结构、周月量比及多周期理由。扫描概况保留实际报价数、有效技术检查数、入池/评分齐全数以及完整性；原模型说明、分项大表、池外名单和逐股错误移至完整JSON/CSV。入口或评分齐全者不足20不凑数。


## 独立MACD监控与本机持仓窗口

手机直接打开[HTTPS交互报告](https://tommy-capital-report.stableokapi18.chatgpt.site)，用同一ChatGPT账号登录；不依赖电脑开机。支持阅读原收盘报告、忽略/恢复、手动观察和私人持仓管理。网页设置存于受登录保护的私有数据库；与电脑本机文件及云端观察设置分别保存。

Windows安装Python 3.11+、更新或下载本仓库后，双击根目录 **`Start-Report.cmd`**（原`Start-Monitor.cmd`仍可）。窗口默认打开最新报告，只监听本机`127.0.0.1:8501`。首次启动安装依赖；之后使用本机环境。见[报告内操作说明](docs/report-controls.md)及[Windows操作说明](docs/monitor-windows.md)。

窗口默认“最新报告”页，在报告内直接忽略/恢复Top10观察股、手动添加/移除观察股、编辑持仓、同步最新报告及刷新五周期监控。原“持续Top10观察池”和“我的实际持仓”页继续保留。手动观察不是持仓，不计正式Top10次数、不参与评分。只填六位代码即可保存，自动尝试核验名称；持仓成本、股数、日期和备注可空。同股多个身份只分析一次。

本机忽略/恢复和手动观察保存在`.tommy/report-controls.json`，同步新报告不覆盖。云端`operations/watchlist-preferences.json`通过报告的GitHub工作流入口管理。本机私有名单不会上传。GitHub Markdown不能运行表单，页顶统一链接HTTPS手机网页；`127.0.0.1`仅用于启动电脑程序后的电脑自身。

手机网页复用原Python引擎已发布的五周期MACD结果，显示真实检查时间。刷新网页只读取已发布结果；新加私人股票没有公开监控结果时会如实显示，完整五周期即时刷新继续使用电脑程序。原评分、排名、累计统计与全市场扫描计划不变。网页源码及部署说明见[web-report](web-report/README.md)。

`holdings.json`（兼容原字符串列表和`--holdings`）与`.tommy/`默认忽略提交。浮盈仅用用户成本与实际未复权报价，自首次监控起记录已观察最大值，不知道过去真实最高浮盈，未计现金分红、送转和费用。窗口可下载最新公开累计历史与忽略设置；**不会上传本机持仓、成本、数量或备注**。Actions也不能读取本机文件。

收盘扫描结束后，`screen.yml`独立步骤仅监控公开累计Top10≥3且未忽略的股票，联合发布新增中文“多周期MACD背离监控”和机器JSON；原Top20与累计观察表保留。云端不增加高频全市场扫描或新定时。本机手动立即刷新独立进行，不依赖Actions排队。重要信号显示匹配价格枢轴、柱波峰值、DIF、首次/确认时间、失效事件及后续条件；配置见`monitor-config.json`，与排名无关。

离线演示：`python -m tommy_capital.monitor_example`，重放已冻结收到的昭衍新药历史日线。样例未附分钟数据，四个分钟周期明确不可判断；不伪造实时行情、不回填Top10历史。完整定义、数据限制和验证记录见[监控与v8说明](docs/macd-monitor-v8.md)。
