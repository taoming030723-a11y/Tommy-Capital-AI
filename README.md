# Tommy Capital AI · 真实 A 股研究版

这是可接入真实数据的沪深 A 股规则筛选器。通过 **AKShare 1.19.1 + 东方财富公开接口**获取行情、已公告财报、前复权日线及分时数据；东方财富日线失败会尝试AKShare腾讯日线，交易日历来自 AKShare 的新浪接口。不需要付费 Token，不调用券商下单接口。

当前仓库此前为空，本版为独立实现，无法声称保留了未提供的旧版13个Agent代码。此版是可审计规则引擎，**没有调用13个大语言模型，也未宣称已验证收益率**。

## 电脑上一条命令运行

安装64位 **Python 3.11或更新版本**，下载本项目并解压，在项目文件夹打开终端：

```bash
python run.py
```

macOS若只有 `python3` 命令，使用 `python3 run.py`。首次启动自动建立 `.venv` 并安装依赖；需要能访问Python包下载源及行情网站。后续直接使用相同命令。

**在A股交易日15:10之后运行**（北京时间与新加坡时间一致），避免盘中行情与昨日K线混用。节假日/周末会按交易日历处理最近已收盘交易日，不把休市当成数据陈旧。

完成后双击 `reports/latest/report.html` 看投资卡片；`rankings.csv` 用Excel打开，代码列需按文本导入以保留前导0。`report.json` 含数据覆盖数量、排除原因、抓取时间、缓存状态、数据哈希及评分分解。每次运行覆盖 `reports/latest/`，要留档可指定输出目录。

```bash
# 默认全市场基本面/估值初筛，再对净利润同比靠前的100只合格股检查技术面
python run.py

# 对全部基本面/估值合格股做深度技术扫描（耗时更长）
python run.py --limit 0

# 小批量先检查网络；5表示技术扫描上限，并非全市场只抓5只
python run.py --limit 5 --refresh

# 保存另一次运行
python run.py --output reports/my-run
```

**100只的默认批次不是全市场最终排名。** 报告会明确标注 `unscanned` 与 `scan_complete`。使用 `--limit 0` 才请求扫描全部基本面合格股；接口失败仍会标记不完整。合格持仓会额外检查，不受批次上限限制。

## GitHub网站上运行

代码全部上传后，进入 **Actions → A-share live screen → Run workflow**，选择扫描上限（默认100；0表示全量）。结束后在该次运行底部下载 `tommy-capital-report`，解压并打开 `report.html`。

工作流为手动运行，未启用定时任务。GitHub服务器的网络出口可能被公开数据源限流；若失败，下载报告检查诊断，也可在自己电脑运行。工作流仅有仓库读取权限，不往仓库写入行情或持仓。

## 你的交易体系如何落实

| 层级 | 本版实现 |
| --- | --- |
| 基本面 | 最新已公告累计营收/归母净利润同比非负、累计净利润与TTM净利润为正、每股累计经营现金流为正 |
| 估值 | 总市值 ÷ TTM归母净利润；PB；同行业正PE样本中位数比值；动态PE单独展示，绝不冒充TTM |
| 日线 | 最近收盘高于MA60，MA20较5根前抬升 |
| 周线 | 完整周收盘高于MA20，MA20较3根前不下降 |
| 月线 | 完整月收盘高于MA20；日/周/月全部确认才进入候选排名 |
| 月线低位增强 | 完整月KDJ J<20且累计利润同比较上一报告期加速，仅为观察加分，不越过战略资格 |
| 60分钟 | 仅对通过战略筛选的已有持仓计算MA20状态和近20根区间支撑阻力参考 |
| 15/30分钟 | 仅对通过战略筛选的已有持仓，以两处已确认价格枢轴检查MACD DIF/KDJ J背离 |
| 风险及复核 | ST/退市名称、流动性、数据完整性、财报时效、估值上限；公告/扣非/负债/订单/减持仍需人工核对 |

周/月线只使用标签日期不晚于已收盘交易日的完整周期，宁可延迟一周期，不使用尚未完成的K线。周五或月底休市时，这个保守规则可能暂时少用最后一周期。日线至少250根，周线至少60根，月线至少24根。

KDJ为9期RSV，K/D按1/3权重递推并初始化50，J=3K−2D；MACD用12/26/9 EMA。背离枢轴需左右各3根确认，因此提示存在确认延迟；相邻两枢轴、60根观察窗、最近枢轴不超过12根。它们只是观察标记，仍需支撑阻力、量价和价格结构确认。A股当日新买股份不能当日卖出，做T要结合已有可卖库存。

## 持仓设置

默认**没有持仓**，不会把旧聊天记录中的持股当作你今天的持仓。复制 `holdings.example.json` 为本机 `holdings.json`，填入你确认仍持有的六位股票代码：

```json
{"holdings": ["600000"]}
```

这只是格式示例，不是荐股。启动器会自动读取本机文件；`.gitignore` 已排除该文件，请勿手动上传真实持仓到公开仓库。

## 阈值与评分

`config.json` 可修改。初始阈值是可调整的研究规则：日成交额≥3000万元、PE TTM≤60、PB≤8、PE≤同行业中位数1.2倍、同行业样本≥5、报告期距今天≤225天。阈值不是你的固定承诺，也不代表适合所有行业；银行、保险等行业的现金流和估值应采用专项分析。

评分满分100：累计营收增长10、累计利润增长15、正现金流5、行业相对估值25、大周期趋势30、利润同比加速5、低J增强5、放量5。增长分数在40%/60%封顶；估值分数=clip((1.5−PE/行业PE中位数)/1.5×25,0,25)。三种趋势各10分，量比为当日量/此前20日均量，≥1.2计5分。分数是规则优先级，**不是收益概率、目标价或内在价值**。

## 财报口径与数据来源

- 抓取最近8个已结束报告期，按每只股票最新已公告记录选择财报，未来公告/缺失公告日期排除。报表金额单位元，同比单位百分数。
- TTM净利润 = 上年全年归母净利润 + 本年累计归母净利润 − 上年同期累计归母净利润。年度报告直接使用全年值；缺数据则不参与TTM估值排名。
- EPS同样桥接但仅近似展示，因为股本变化会影响可比性；估值用市值/净利润，不用桥接EPS。
- 财报增长为**累计同比**，不是单季同比；“改善”是累计同比增速较相邻上一报告期增加的代理，不能据此断言盈利拐点或订单改善。若缺相邻上一报告期，不给改善加分。
- 行业PE中位数使用当前已取得的沪深、非ST且0<PE TTM≤200样本；异常及缺失数据不填零、不编造。
- 现金流表只提供每股累计经营现金流；暂未抓取扣非利润、资产负债表、订单/IR文本或股东变化，投资卡片列出人工复核项目。
- 日线/分时用前复权，不能直接当作历史时点可得数据回测；财报源可能发生重述。前复权出现非正历史价时本版保守拒绝该股票的技术计算。
- 抓取时间是本机获取时间，不等于交易所逐股报价时间；日线必须覆盖最近已收盘交易日。停牌/过旧K线不给排名。行情表不提供逐股时间戳，所以无法保证逐股报价都是最新。

官方接口说明：[AKShare股票文档](https://akshare.akfamily.xyz/data/stock/stock.html)。使用 `stock_zh_a_spot_em`、`stock_yjbb_em`、`stock_zh_a_hist`、`stock_zh_a_hist_tx`、`stock_zh_a_hist_min_em` 和 `tool_trade_date_hist_sina`。它们是公开网络接口，可能延迟、限流、超时或改版，不保证持续可用。

## 失败不会变成“成功排名”

单个接口在独立子进程中运行，有硬超时和有限重试；过期缓存不会降级使用，也没有演示数据回退。缺失财务字段/缺失TTM/技术数据滞后均排除。行情或全部财报失败时输出失败报告并退出；部分数据失败输出已验证范围内的候选并明确标注不完整。

退出码：0=所请求批次无数据错误（批次有限仍可能未扫完整市场），1=部分数据失败，2=核心数据或配置失败。报告的完整性以 `status`、`coverage`、`scan_complete` 为准。
